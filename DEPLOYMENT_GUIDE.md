# M.A.D (Money Analysis & Decisions) — Production Deployment & Scaling Guide

This guide documents the target production architecture, setup instructions, and scaling steps for M.A.D.

---

## 📘 Production Setup & Configuration Reference

### 🗄️ Database: Neon (PostgreSQL)
* **Project Name**: `mad-backend`
* **PostgreSQL Version**: `18`
* **Region**: `AWS US East 1 (N. Virginia)` or `AWS Asia Pacific (Sydney)`
* **Initialization**: Automatically creates all database tables (`initDB()` in `backend/db.js`) on startup.

### 🖥️ Backend: Render (Express API)
* **Service Type**: Web Service
* **Root Directory**: `backend`
* **Build Command**: `npm install`
* **Start Command**: `node server.js`
* **Live URL**: `https://m-a-d-money-analysis-and-decisions.onrender.com`
* **Required Env Variables**:
  | Variable | Value | Purpose |
  |----------|-------|---------|
  | `DATABASE_URL` | `postgresql://...` (from Neon) | Database credentials |
  | `SESSION_SECRET` | *(Auto-generated by Render)* | Session cookie security |
  | `GOOGLE_CLIENT_ID` | `805109258892-j7smef21ov8r4rraqr5mjfcg9cibsvap...` | Google Sign-In Integration |
  | `NODE_ENV` | `production` | Enables production optimizations |
  | `FRONTEND_URL` | `https://your-vercel-frontend.vercel.app` | **CORS & Cookie restriction** (Update after Vercel deployment) |

### 🌐 Frontend: Vercel (Static Web App)
* **Project Type**: Static site (Framework: `Other`)
* **Root Directory**: `frontend`
* **Build / Output Commands**: Leave empty (defaults)
* **API Base URL Config**: Injected in `frontend/index.html` via script:
  ```html
  <script>
    window.__MAD_API_BASE__ = 'https://m-a-d-money-analysis-and-decisions.onrender.com/api';
  </script>
  ```

## 🔒 Post-Deployment Checklist (Crucial)

Immediately after Vercel finishes deploying the frontend, complete these two configurations:

### 1. Enable CORS & Cookies (Render)
1. Copy the live Vercel URL (e.g. `https://m-a-d-money-analysis-and-decisions.vercel.app`).
2. Go to your **Render Dashboard** → **MAD Web Service** → **Environment**.
3. Edit the environment variables and add `FRONTEND_URL` with your Vercel URL.
4. Save changes. Render will automatically redeploy the backend with proper CORS credentials and secure cookie handling.

### 2. Configure Google OAuth (Google Cloud Console)
1. Go to [Google Cloud Credentials Console](https://console.cloud.google.com/apis/credentials).
2. Edit your OAuth 2.0 Client ID.
3. Under **Authorized JavaScript origins**, add:
   - `http://localhost:3002` (Local testing)
   - `https://your-vercel-frontend.vercel.app` (Production URL)
4. Under **Authorized redirect URIs**, add:
   - `http://localhost:3002/api/auth/google/callback`
   - `https://m-a-d-money-analysis-and-decisions.onrender.com/api/auth/google/callback` (Render Backend redirect)
5. Save changes. *(It might take up to 5-10 minutes to propagate globally).*

## 🛠️ Future Scaling & Tech-Stack Upgrades

As you expand the M.A.D application, follow this manual to scale up each component:

### 1. Database (Neon) Scaling
* **PgBouncer Connection Pooling**:
  - Neon includes built-in connection pooling. If you start getting `too many clients` connection errors from Postgres under heavy traffic, switch your `DATABASE_URL` host to Neon's pooler host (which has the `-pooler` suffix in the Neon dashboard).
* **Branching for Safe Schema Upgrades**:
  - Use Neon's **Branching** feature to clone the production database schema and data into a temporary developer branch. Test any future SQL alterations or schema updates there before running them in production.
* **ORM Migrations**:
  - If you switch to an ORM like **Prisma** or query builder like **Knex**, replace the custom `initDB()` in `backend/db.js` with database migration scripts (`npx prisma migrate deploy` in Render build step) for standard enterprise CI/CD.

### 2. Backend (Render) Storage & Autoscaling
* **Persistent Uploads (Profile Pictures/Avatars)**:
  - Render's default instances use ephemeral disks (wiped on server restarts or redeploys). Currently, uploaded avatars in `backend/uploads/` will disappear when the backend updates.
  - *Option A (Render Disks)*: Go to Render settings → **Disks** → **Add Disk**. Mount a persistent disk at `/opt/render/project/src/backend/uploads`.
  - *Option B (Cloud Storage - Recommended)*: Rewrite the upload route in `routes/auth.js` to upload images directly to **Cloudinary** or **AWS S3** and store the image URL string in the database.
* **Horizontal Auto-scaling**:
  - If you upgrade your Render plan, you can scale the instance count. Because we migrated Express sessions to PostgreSQL (`connect-pg-simple`), session states are automatically shared across all server instances, allowing seamless load balancing.

### 3. Frontend (React / Angular) Framework Migration
When migrating the frontend codebase from pure HTML/CSS/JS to a framework like React (Vite) or Angular:
* **Vercel Build Configurations**:
  - In Vercel Project Settings, change **Framework Preset** from `Other` to `Vite` or `Angular`.
  - Set **Build Command** to `npm run build` or `ng build`.
  - Set **Output Directory** to `dist` or the framework's default build directory.
* **Environment Variables (Dynamic API Base)**:
  - Remove the inline `<script>` snippet from `index.html`.
  - In your React/Angular source code, fetch the API URL base dynamically:
    - For React + Vite: `const API_BASE = import.meta.env.VITE_API_BASE_URL || '/api';`
    - For Create React App: `const API_BASE = process.env.REACT_APP_API_BASE_URL || '/api';`
  - In your Vercel Dashboard → **Project Settings** → **Environment Variables**, add:
    - Key: `VITE_API_BASE_URL` (or the equivalent framework variable)
    - Value: `https://m-a-d-money-analysis-and-decisions.onrender.com/api`
  - Vercel will inject this variable during compile-time, keeping your code clean and separation of environments intact.
